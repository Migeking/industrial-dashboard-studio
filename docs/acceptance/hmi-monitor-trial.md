# HMI 只读值守验证

以预处理进水小工段为独立工程，使用本机只读 REST 台架同时提供当前值、历史行和告警行。07 号经典监视和 25 号工况、趋势及报警显示另有各自的画面回归。

| 数据 | 台架数据约定 | 验证结果 |
| --- | --- | --- |
| 当前值 | `points[]` 的数值点提供值、质量和接收时间 | 液位原码 16000 按 0–6 m 量程换算为 4.50 m |
| 历史 | `points[]` 的行数据集包含时间、数值和逐行质量 | 画布趋势和设备趋势按实际时间排序，在坏质量样本处断开 |
| 事件 | 行数据包含事件时间、级别、状态和内容 | 时间按实际时刻排序，上游“活动 · 待确认”和“已恢复”都可追溯 |
| 中断和恢复 | 测试源模拟 503 后恢复 | 已发布画面显示离线，已恢复后自动重新显示现值、历史和事件 |
| 连通但停止更新 | HTTP 继续返回 200，数据时间戳停止推进 | 超过工程的最大数据年龄后显示过期，收到新数据后自动恢复 |
| 发布回退 | 在同一工程发布两版 | 选回旧版并重读发布数据，标题和文档与旧版一致 |

台架通过 `python -X utf8 tests/studio_monitor_trial_check.py` 验证。值守画面和断线截图保存在 `works/hmi-monitor-acceptance/`。本机测试使用 300 ms 刷新设置，单次测得离线识别约 109 ms、恢复约 313 ms。现场周期由站点负载和后续试运行数据确定。

历史和事件可经上游聚合为同一只读快照。告警列表默认每页八条，可按工程设置调整。翻到后续页时保留进入时的事件快照，并提示实时列表的更新。点击「返回实时」或回到第一页时恢复最新读数。数据过期或中断时清除查阅快照。可查阅范围和告警确认状态由上游提供。现场试点需明确接口保留时间、工作画面、值守时段和故障演练窗口，再记录 24 小时和 72 小时结果。

在「交互 → 打开趋势面板」选择已绑定历史数据集的槽位，可配置面板使用的时间、数值和质量字段。字段留空时使用 `time`、`value` 和可选的 `quality`。明确指定质量字段后，缺少该字段的历史行也会形成断点。

图表序列和列表可直接在「外观」选择已配置的测点。绑定行数据集后可展开「字段样本」，查看前 12 行中出现的列名、类型和样本值。字段输入会按各自数据集提示候选，也可手填路径。不同历史数据集可为各序列单独指定时间字段，留空时沿用图表横轴字段。配置了质量字段的序列遇到坏质量样本会断开。

在「数据连接 → 行数据集 → 数据集行筛选」选择字段并填写匹配值。已有样本时可从字段和值的候选中选择，并核对命中行数。字段支持 `equipment.id` 一类的嵌套路径，按文本精确匹配，区分大小写，数值 0 和布尔 false 也可用。未命中显示空列表或空曲线。趋势和设备详情绑定同一数据集测点时共用筛选，告警会先筛选再排序和分页。要用同一份上游数据配置另一台设备，可以复制数据集，再修改匹配值。

发布画面右下角的「测点诊断」列出本画面所用点位。原值、工程值、质量原因、读数时间和接收时间可一起核对。一条测点关联多个对象时，可分别点击名称在画面中定位。异常期间可保留收到过的诊断原值，工程值随质量失效而撤下。

新发布版本随工程文档记录点表、已引用图稿和部署文件指纹。版本窗口可检查工程文档与部署文件是否仍和发布记录一致。回退恢复该版工程和点表，部署文件继续使用当前安装版本。历史版本保留原有的发布记录。

在「项目管理 → 工程操作」可下载工程备份。备份包含已保存的草稿、发布历史、当前展示版本和发布追溯记录。由「导入工程」恢复时会建立独立工程。恢复过程校验版本、展示指针和已有的文档指纹，也支持此前直接保存的 `project.json` 工程状态文件。备份中的工程配置可能包含现场地址和样本，应保存在项目约定的本地目录。

## 07 号试点准备

已选定 07 号 A²/O 经典上位监控。在本地隔离入口创建试点副本，复核发布画面的 43 个图元、11 条管线和 41 处绑定。原工程的草稿和发布均使用本地演示 JSON。32 项数据中有 18 个数值、10 个开关量和 4 个数据集，数据集分别为出水、能耗、告警和历史。需求点表导出到本地 `works/hmi-monitor-acceptance/scene07-required-points.csv`。现场计时在 07 工程的业务位号和上游历史、告警数据源接通后开始。

切换到 REST 后，读取包含 `points[]` 的样本，点击「对照现有点位」。界面按已有接口编号或相同业务编号预选同类型测点，也可选择名称不同的接口测点。表内检查原值、现有换算后的工程值和质量原因，再采用结果并应用数据配置。工程编号和原有画面绑定保持一致。未选择的点位保留现有配置，发布前质量检查会列出未取到的读数。采用后的点位读取 `value`、可选 `raw`、`quality`、`timestamp` 或 `receivedAt`，重复的接口编号不会进入候选。整次连接和点表变更可用画布撤销恢复。

对照窗口可导出及导入 UTF-8 CSV。保留「画面业务位号」列，把 REST 样本中的 `points[].id` 填到「现场点位或字段」，即可重新导入已有的 07 号现场交接表。空白项保留当前选择。未知或重复的画面位号、样本中找不到的编号及类型不匹配会逐条列出，整份出错文件保持原预览选择。导入后仍在同一张表中试读，采用对照并应用数据配置后才写入工程草稿。

以完整 07 号工程副本接入本机只读 REST 台架，32 个点中 28 个按相同编号匹配，4 个分别选择新的现值、联锁、历史和告警编号。已发布版本保留 43 个图元、11 条管线和 41 处绑定，浏览器验证了四类数据更新及中断恢复。该测试使用合成数据，现场试点单独计时。

07 号重建工程的内回流比、外回流比和空气总管频率已接入原有业务位号，画面共 44 处绑定，仍使用 32 个业务位号。只读 REST 台架切换坏质量、缺值和离线时，行内标签撤下数字并显示状态，恢复后显示新读数。

### 设备协议与历史告警一起接入

OPC UA／Modbus TCP 页的「历史与告警接口」接收只读 REST 的 `points[]`。每个数据集记录提供 `id`、`kind: "dataset"`、行数组 `value`、`quality` 和本次快照的 `timestamp` 或 `receivedAt`。行内历史和告警时间继续由各自组件字段读取。试读后，用现有画面业务位号选择接口数据集，也可从样本新增数据集后回画布绑定组件。设备的现值与联锁继续来自所选工业协议。

两路各自刷新并显示连接状态。一个数据集过期只撤下该数据集，接口中断撤下所有关联数据集，设备现值继续更新。设备采样中断时，正常的历史和告警仍可查看。离线演示使用导出时捕获的数据集，不保留接口地址。

台架回归用 `python -X utf8 tests/studio_engineering_ui_check.py` 验证了关联、试读、发布、两路各自中断和恢复、快照过期、重复数据集编号及离线导出。

在完整 07 号本地副本中，28 项模拟设备点经 Modbus TCP 读取，出水、能耗、历史和告警 4 项经 REST 关联。画面使用 31 项，点表中的进水流量位号尚未绑定。短时断线演练记录了 4 个 REST 数据集离线和恢复，画面中的 Modbus 现值持续有效。

### 24／72 小时观测记录

从产品工作树运行 `tests/studio_monitor_soak.py`，传入已发布的监视页面及独立输出目录。现场使用 `--scope field`，本地回归使用 `--scope bench`。下面以 24 小时为例，72 小时时将秒数改为 `259200`。

```powershell
python -X utf8 tests/studio_monitor_soak.py --view "<已授权的 /view URL>" --scope field --seconds 86400 --out "works/scene07-field-24h"
```

脚本在独立浏览页观察项目的测点诊断。默认每 15 秒记录一次连接状态、画面点位质量与时间、图元和管线数量、趋势样本数及告警表渲染行数。记录保留点位编号，不写入原值和工程值。通过 `--interval-seconds` 和 `--max-gap-seconds` 调整观察间隔与允许缺口。发布版本在开始、结束及每 15 分钟核对一次。超过观测缺口、版本变化或浏览器错误时写入中断结果，已记录的样本继续保留。

现场模式在启动时要求工程指纹和当前部署都与发布记录一致。启动前确认数据源和试点范围已经授权。试点期间的发布变化会中断当前记录，便于按版次复核。

`observations.jsonl` 保存逐次观察。`results.json` 汇总各连接区间的首末观察时刻、首次观测掉线到首次观测恢复的间隔、逐点质量及原因，以及图元、管线、趋势样本和告警行数的最小值与最大值。收到有效数据时记录浏览器接收年龄。配置了上游时间字段的点位另记样本年龄和上游时间领先浏览器的次数。使用独立历史与告警接口时，报告同时记录该接口的连接区间，并标出由该接口提供的测点。时间差受采样间隔和源时钟影响，现场验收按约定负载、时段和故障演练一起判定。完成状态表示记录覆盖了设定时长。

## 25 号工艺监视台架

以已组态的 25 号工程为输入，接入本机只读 REST 快照并重新发布。验收覆盖双趋势 8／24 小时显示、离心脱水机故障与告警联动、断线恢复和版本回退。只读浏览中，工况与 PAM 调节禁用，趋势窗口保留交互。验收同时检查浏览器请求和上游收到的请求。

告警组件可在「外观 → 告警定位字段」指定事件数据中的设备引用。字段值使用本画面的图元编号或唯一设备名称。例如事件中的 `deviceRef` 等于组态中的设备名称，就能从告警行打开该设备的只读详情。引用缺失、设备名称重复或设备不可见时，设备列显示空位。

在产品工作树运行 `python -X utf8 tests/studio_scene25_readonly_check.py`。默认读取 `works/scene25-refinement/project.json`，可用 `--project` 指定等价的 25 号本地演示工程。报告和截图默认写入 `works/scene25-readonly-acceptance/`。

## SS-02 第三工段空白组态台架

取 SS-02 污水厂输送出水总管的一条示范支路，沿用本地设计资料中的 FT-11 总管流量、PET-11 总管压力和出水蝶阀关系。从项目管理新建空白工程，经编辑器添加 13 个图元及 7 条管线，配置 7 个模拟点位并发布。压力台架量程为 0–0.30 MPa，原码 12000 显示 0.15 MPa，3999 显示无效并保留诊断原值。流量 0.85 m³/s 直接读取，故障状态下的零值继续有效。该量程用于模拟回归，现场控制参数和验收另行确认。

验收覆盖底板上起管、在进口释放后保留管口绑定、历史坏数据断点、告警定位、断线恢复、发布回退与横屏离线导出。上游写请求和离线 HTTP 请求均为零。用 `python -X utf8 tests/studio_ss02_readonly_ui_check.py` 可重跑，从空白工程开始。报告、截图、工程备份及离线演示默认保存至 `works/ss02-readonly-trial/`。该回归由浏览器自动化操作，现场工程师独立组态和长期值守仍需现场验收。
