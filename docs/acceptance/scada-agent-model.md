# A3：自然语言画图入口与本机模型接入

本轮在 `codex/visual-config-platform` 实现了真实模型调用路径和编辑器对话入口。2026-11-19 经用户授权重新下载并校验 `qwen2.5-coder:7b`，已通过 13 号工段的真实模型增量绘图、绑点和 UI 发布链路。详细过程及视觉差距见 [13 号真实模型验收](scene13-real-model.md)；这项结果不等于原版三维画面还原通过。

## 用户从哪里开始

本轮测试入口为 `http://127.0.0.1:8139/?assistant=1`，发布页为 `/view`，使用独立的本地演示项目，不替换原 8099 项目。进入时右侧直接显示「AI 画图助手」；普通入口可点顶部「AI 画图」。此前 8138 是模型修复前的独立测试入口。

1. 在「设计需求」里描述设备、流程方向及要显示的数据，也可点「画一个水处理工段」「补齐管道」「匹配测点」填入示例。Ctrl+Enter 提交。
2. 有点表时点「使用当前点表」。不允许测点也能先绘图，必填槽位保留待选。当前演示项目为 25 个明确标记的本地模拟点，未接现场设备。
3. 点「生成设计预演」。等待时显示耗时，可取消；关闭助手、换页会取消请求，迟到结果不应用。需求或模型调用失败时保留输入，显示原因。
4. 对话显示方案、未决问题、模型和耗时。画布金色轮廓提示本批对象；绑定列表显示设备名称和槽位，可直接重新选点。预演期间草稿不变，保存与发布暂停。
5. 点「确认应用到画布」才改草稿，整批形成一条撤销记录。助手保持打开，可以继续提需求；关闭再打开保留当前会话的对话、允许点表和未发送输入。切换画面会清空对话。浏览器重载不保存聊天记录。
6. 按原流程保存、预览发布与离线导出。待绑槽位继续经过原发布检查。固定 05 泵站任务和 JSON 调试入口均放在折叠区。

## 实现边界

- `GET/POST /api/assistant/config` 读写服务端独立的 `STUDIO_DATA_DIR/model.json`，不写入项目或离线文件。默认本机 Ollama、`qwen2.5-coder:7b`；设置中可改模型与地址。兼容 Chat Completions 接口的密钥只由服务端环境变量 `STUDIO_LLM_API_KEY` 提供，前端不读取密钥。
- `POST /api/assistant/propose` 接收当前页文档、需求、已允许点集与最多六条近期对话。只向模型发送几何、端口、名称、现有绑定和允许点的 ID/类型/单位；不发送 source、协议地址、点表路径、实时值、图片和凭据。
- Ollama 使用原生 `/api/chat`、流式 NDJSON 与 JSON Schema、8192 上下文，避免慢模型超过响应头等待期限；兼容接口使用 `/chat/completions` JSON 模式。最多三次校验修正，整个调用期限十分钟，可取消；本机模型可能较慢，此期限不是性能承诺。
- 现有设备以唯一位号/名称供模型引用，实际变更仍使用工程 ID。按设备实际槽位、点类型及已有位号分组收窄候选；同类型的跨设备误绑也会拒绝。未采用位号分组的点表仍由类型和允许范围校验，点义需人工预演检查。
- 模型返回通用图元图结构，由 `screen-intent.mjs` 编译为原有六类命令。图结构编译器独立于场景编号，不通过关键词选择预制场景。支持文字图元内容，缺少标准接口时按端口定义补接口。模型不直接修改草稿、发布或写设备。
- 仍由 `executeScreenCommands` 校验范围、引用、锁定、测点类型、单位和允许范围。模型结果对照发起时修订，应用时再次校验。已有图元位置默认保留，同名同类型复用；更换已有绑定仍回属性面板。
- 没有可应用变更时说明事实；需要澄清时显示问题，不制造图元。模型方案的拓扑、美观和点义仍需工程师检查，格式通过不代表工艺正确。
- 对“本批只补 N 个图元”“本批新增 N 条管道”等明确的当前批次数量要求，约束输出下限并检查实际新增命令数；数量不足进入有限修正，不从工艺名推断数量。预演新增接管清单，显示设备名、接口和转折点数量。复杂工段的首个界面示例改为先画主流程，提示分批完成补图、接管与绑点。
