## 实测发现并修复的问题

| 问题 | 修改与复查 |
| --- | --- |
| 模型使用长 UUID 时会把连接顺序和设备对应错 | 模型上下文改为唯一设备位号/名称，编译时解析回正式 ID；重名拒绝。逐条检查 12 条真实工艺关系 |
| 泵频率写到不存在的 flow 槽位；同类型数值绑到其他设备 | 按每设备实际槽位、点类型、已有位号分组生成候选 Schema；编译器再次拒绝不支持槽位、类型/单位和归属冲突。检查全部 25 个绑定身份，不能只看数量 |
| 已有设备绑点重复输出几何字段，容易重建设备 | 支持仅 key/bindings 的增量条目；只在明确 move 时移动，保留原绑定 |
| 明确要求补 7 个图元或 12 条管道却只输出第一项 | 对“本批只补 N 个图元”“本批新增 N 条管道”等明确的当前批次数量指令设置输出下限，并核对实际新增命令数；不足或重复引用进入原有有限修正。没有明确数量时不猜测设备/管道数量 |
| 本机慢推理超过非流式响应头期限 | Ollama 使用流式 NDJSON，沿用总期限、取消和有限修正；模拟传输回归覆盖分块和取消 |
| 管道漏接口、漏折线，默认方向可能错 | 结构化输出要求每管显式给出双方接口和 vertices；提示明确遵守指定端口。最终验收核对接口和指定折线；模型仍可能犯错，保留人工预演 |
| 长会话看不到新方案与应用检查区 | 对话跟随新消息滚动，方案出现后显示本批检查区；应用后保持助手打开 |
| 操作清单只有管道名称，难以核对接口 | 预演增加「核对接管」，用设备名称、双方接口及转折点数量列出每条新管道 |
| 首个示例把复杂工段的绘图、接管和绑定全压在一批 | 示例改为先画主流程，并提示先主流程、补设备、接管、最后绑点，降低小模型返工负担 |

迭代期间确实发生过错误拓扑、槽位幻觉、同类型错绑和错误接口；未把这些尝试计为成功率，错误版本未发布为最终结果。早期一份错误点绑定曾应用到独立测试草稿，由断言发现后清除重测，不能将其描述为“格式校验就保证工艺正确”。这些案例促成候选约束与语义断言的补充。每次模型内部最多 3 次修正不等于工程端无返工。
