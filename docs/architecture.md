# 产品架构基线

当前工作区采用“场景先独立、能力逐步抽取”的迁移策略：三套样板仍可独立展示；`packages/` 已提供设计 Token、状态组件、全屏/时钟运行时和三类数据适配器，后续在不破坏样板的前提下逐步替换重复实现。

## 数据边界

当前三套场景仍使用内置演示数据。后续统一定义 `scenario -> data adapter -> runtime` 边界：

- `demo`：本地定时变化，供展示和测试。
- `rest`：读取项目接口，供轻量交付。
- `websocket`：接入实时设备网关。

在数据契约明确前，不把演示页面直接宣称为现场 SCADA 系统。

## 横屏体验

入口层负责方向提示、场景选择和全屏；场景层负责 1920×1080 基准画布、缩放和工业信息层级。移动端后续增加“核心流程优先”的横屏布局，不将完整桌面信息强行压成竖屏。

## 迁移原则

`MyWord` 中的原始成果保留为来源和运营资产；本工作区是后续产品开发的唯一工作目录。两边不做反向自动同步，避免内容项目和产品代码再次互相污染。
