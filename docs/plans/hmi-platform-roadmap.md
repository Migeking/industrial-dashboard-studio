# 工业 HMI 平台产品与工程路线

审计日期 2026-11-19。以当前设计器、项目管理、案例库与本地验收记录为基础。竞品对照来自官方手册和项目说明，未进行同硬件性能对打。

## 1. 产品目标和交付口径

保留 Vue、X6、ECharts、工程文档和现有发布链。以水务工艺为首个产品领域，把平台做成工程师可自行完成点表配置、工艺搭建、发布、交接和排障的 Web HMI。案例库保留原版与可编辑工程的关系。复用以点位、设备类型和成套工艺单元为主，整页示例用于验收和入门。

- **监视版 1.0**：新站点从连接、导点、统一换算、拖放单元到发布完整走通。设备反馈、质量、历史和事件在同一工作流中可辨识，发布可回退、恢复和复诊。
- **操作扩展**：在监视版通过现场试点后，针对一个明确设备和动作接入已有控制服务，验证权限、操作确认、业务联锁、拒绝、回执、实际反馈和审计。以已批准的设备控制边界定义可用范围。
- 运行界面维护「模拟／现场／离线快照」语义。PLC／控制器负责实时联锁、故障锁存、停机、复位和防旧请求误启动。项目数据与控制进程的生产化边界在试点部署时确定。

## 4. P1 点表、换算与诊断

**目标**是工程师在点表里完成配置和试读，画布、详情、趋势、报警使用同一工程值。

当前 `model.mjs` 已有倍率、偏移、枚举和时间年龄校验。部分北向导入入口也带固定原码边界。本阶段把已有能力收束成一个转换合同，并保留旧工程迁移路径。

| 层 | 必要能力 | 首批验收 |
|---|---|---|
| 采集与解码 | Modbus 单元号、功能码、零基地址、类型、字节序。OPC UA NodeId、原生类型、源时间戳及质量。区分建议周期、请求周期和实际采样周期 | 代表点支持两种协议只读试读。同一实际周期在配置、试读和发布端可见。修复 UI 200 ms 与桥接 500 ms 下限不一致 |
| 工程转换 | 保留恒等、倍率／偏移和枚举，新增两点线性映射、固定 4–20 mA 原码预设和受控单位换算。设备配置中明确输入是原码还是已换算工程值 | 量程 0–6 m 时，4000→0 m，12000→3 m，16000→4.5 m，20000→6 m。原码越界显示异常原因。已是米的点直接使用，避免重复换算 |
| 质量与时间 | 统一输出原值、工程值、单位、源时间、接收时间、质量及原因。可选显示最后有效值，明确标记时间和过期状态。现值、趋势和报警用有效性策略分别处理 | 0、false、坏质量、越界、过期、离线、重连逐项验证。已归一化的数字量 True/1 表示有效，无二次反相 |
| 表单与批量工程 | 同屏预览「地址→原码→工程值→质量」，点表批量套用、检查差异、错误逐行定位、可撤销。工程量程、仪表显示范围、报警阈值分别配置，保留含义和单位 | 用一份含 DI、液位、压力、流量、频率、浮点字序的样本导入并绑定 10 个代表测点。记录耗时、误配和修正步骤。全部展示入口算值一致 |

所有本用户控制器、扩展模块及采集器的 4–20 mA 模拟量沿用约定的 4000–20000 原码端点。物理工程范围、单位和阈值使用点表与项目参数。无效输入保留诊断原值，禁止当作有效工程读数触发正常显示。小数位仅用于显示，不参与报警判断。

实现入口优先在 `apps/scada-designer/studio/model.mjs` 和点表面板收敛，并用同一函数完成预览与发布。对旧 `scale/offset`、枚举和历史绑定建立等价迁移验证。数值表达式暂以可校验转换类型为主，通用脚本从实际需求立项。第二数据源在站点证明确有需求时引入稳定 sourceId，现有单源项目可迁移为默认源。首批现场试点优先使用上游聚合的只读数据。

## 5. P2 成套设备与图源

**目标**是拖入一个工艺单元就得到可连接、可绑定、可下钻的设备实例。统一外观、端口和运行反馈以后，可跨项目复用。

| 内容 | 最小合同 |
|---|---|
| 来源与外观 | 每个图源有 ID、版本、出处、使用授权、校验值、缩略图和适用尺寸。经典 P&ID 用可缩放的工程符号。写实 2.5D 用本地透明 WebP 或经过授权的 CAD 渲染、照片。生成图须过工艺结构与管口复核 |
| 工艺结构 | 一套设备类型管理子设备、工艺口、测点角色与详情视图。按工艺定义原水、清水、加药、排泥、排气等端口，标明方向和介质。经典与写实外观各有自己的锚点，共用端口语义 |
| 运行层 | 运行、停止、故障、未知及质量覆盖层独立。关键读数可被搜索、点击和绑定。外部管段由编辑器绘制，设备素材表达设备外形及与图稿固定关联的内部结构 |
| 分发与更新 | 项目、公司、内置资源可先用同一结构保存，正式资产引用固定版本。导入、替换与升级前显示端口和必绑槽差异，保留已连接实例的引用。离线包按实际引用收录素材，生成产物可重建 |

首批只做三组高价值工艺原型。

1. **05 泵阀单元。** 泵、阀、止回、液位、流量和就地／远程反馈。作为电气状态与接管最小基准。
2. **13 高效沉淀与双加药单元。** 快混、絮凝、斜管沉淀和回流排泥，PAC/PAM 的反馈分别绑定。作为成套图源与多槽位基准。
3. **25 污泥脱水线。** 螺杆泵、熟化投加、双线离心、回流与泥饼外运。作为多支路、图源组合和离线包容量基准。

三组分别在库卡片、画布、发布和离线上检查同源图片。对缩放、替换、移动、图源缺失、质量失效及工艺线路交叉做回归。维持当前直角走线、手动走廊和跨线桥。新增验收检查管口漂移、穿过仪表文字、两条不同介质重叠、跨线误读和单元尺寸变化后的端点连接。其它成套装置按下一站实际工艺补齐。

## 6. P3 工程发布与值守

1. 画面编排参考 GoView。补字段浏览、字段类型与样本预览、图表列映射和可复用过滤配置。现场单位和质量使用 P1 合同。
2. 发布包绑定工程、点表、设备图源版本和运行依赖。发布前能定位缺点、非法量程、资源缺失、无效动作。上线后复核当前工程、发布版和服务端实际读取一致。验证版本回退和从备份恢复。
3. 运行端接入上游历史和事件接口，明确来源、时间基准、单位、质量、分页和断线表现。当前值、历史曲线、告警列表和联锁回执可定位对应设备。报警确认及审计若用于现场，作为有明确授权的独立业务接口验收。
4. 选两个真实工作模式验收。07 验证上位监视、异常定位和趋势，25 验证工艺总览及成套设备复用。另选一个不同站点，从空白工程搭建一个小工段，观察工程师能否独立完成。先做 24 小时试运行，再做 72 小时运行、断线重连和回退，记录点数、画布负载、刷新延迟和恢复时间。是否达到现场要求由与试点约定的周期和负载判定。

## 7. P4 受控操作与 Agent 边界

首个操作试点只选一个获准设备和清晰动作。复用现有控制器与网关规则，将工程值、允许区间、许可、确认、控制回执、实际反馈和审计对应到同一请求。台架测试覆盖未许可、坏质量、重复点击、超时、拒绝、断线恢复、急停和旧请求。超时显示结果待确认，读取现场反馈后处置。真正的机械动作单独验收。现场所需的身份、权限范围和保护由试点合同确定。

AI 使用现有命令预演、校验、确认与撤销。优先辅助选库、提议布局、匹配槽位、生成换算候选和定位工程错误，所有候选都进入统一校验。保持运行命令由既有控制服务和人员操作流程处理。

## 8. 实施门槛和优先级

| 阶段 | 预计投入 | 放行证据 |
|---|---:|---|
| P0 基线 | 2–4 人日 | 现有功能可重建、工程可恢复、分支内容可审阅 |
| P1 点表与换算 | 5–8 人日 | 两个受控协议源和代表点位结果一致，原码、工程值、质量可诊断 |
| P2 工艺单元与连线 | 6–10 人日 | 05／13／25 通用单元跨工程复用，图稿、管口、状态、发布和离线一致 |
| P3 监视版试点 | 7–12 人日加运行观察 | 07／25 及新站点小工段可搭建、发布、诊断、恢复并完成试运行 |
| P4 操作扩展 | 按试点接口单独估算 | 一个明确动作通过软件台架、设备联锁、真实反馈验收 |

估算按一个开发者、现有代码可复用、点表与授权图源已具备计算。P1 的试点点表和 P2 的图源盘点可并行。首个实现切片是 P0 保全之后，在点表上试读一组 4–20 mA 液位和已换算流量，让原码、工程值、仪表和趋势对齐。第二个切片以 13 号高效沉淀成套装置检验设备合同。发布前继续运行仓库静态场景、交互和设计器回归；涉及现场的测读与设备验证按批准范围单独记录。
