# SCADA 与驾驶舱画面设计器：重订实施方案

版本：1.3，2026-11-18。工作分支：`codex/visual-config-platform`。本轮按 M1—M4 整体目标继续实施，并将用户可定义的数据槽位与连接点纳入所有阶段；各阶段完成情况以实际验收为准。

**目标是让工程人员从空白画布设计新画面。** 同一个编辑器既能画泵站、池体、仪表和管网，也能排版指标、图表和告警列表。01—30 号保留为视觉与业务参考，不再以迁移模板数量推进开发。

本方案取代 [原 V2 升级计划](editor-v2-upgrade.md)。原计划后续 P3/P4 模板迁移暂停。01/05 的显示还原和数据链路成果保留，但不作为“通用设计器已经完成”的证明。

## 1. 为什么必须调整

本次复核的是 `2bceadc` 的实际代码，而非按组件名称判断能力。

| 实际情况 | 对用户的影响 | 本次决定 |
| --- | --- | --- |
| `nativeBlank()` 从 01 文档删去子节点，仍继承其皮肤、数据和配置 | 所谓空白画布依赖原场景 | 新画面从空对象、空绑定、无场景皮肤开始 |
| `nativeRecipes` 仅五项，按原场景 CSS 类名或 ID 提取 | 插入的是四池、泵组等片段，无法自由绘制新工艺 | 建立独立基础图形与单设备图元；组合件由用户组合后保存 |
| 管道通过修改已有 SVG 路径坐标编辑 | 移动泵阀缺乏可靠的连接关系，也不能自然画新管网 | 管道端点绑定设备端口，转折点单独保存 |
| DOM 对象可选中，但语义和样式依赖原页面 | 对象多不等于工具齐，开发者仍需补页面代码 | 几何、外观、动态、事件有稳定且可编辑的属性 |
| 原验收以 01/05 固定样本截图及片段复用为主 | 高 SSIM 只能证明显示效果，无法证明用户能设计 | 主验收改为从空白完成两种全新布局，完整经过发布 |

旧成果中继续使用：连接与点表管理、只读 OPC UA/Modbus 桥接、质量与时间归一化、草稿/版本/发布服务、本地资源以及已有演示。新画布不继续绑定原场景 DOM/CSS。

## 2. 用户实际怎样完成一张画面

以“新建一张三泵供水监控画面”为主路径：

1. **新建画面**：默认空白，1920×1080；选“工艺监控”或“数据驾驶舱”只改变默认主题、常用工具和字号，不加载整页内容。
2. **画框架**：画矩形分区、标题、分隔线，放底图；支持直接画、拖入和数值微调。背景可锁定，放置新对象不被背景挡住。
3. **放设备、连管道**：分别放一个池体、三台泵、两个阀门和仪表；从设备端口拖出管道，点击增加转折和分支。设备复制后单独命名、换向、调整尺寸；移动设备时保持连接。
4. **放数据显示**：加液位棒图、频率数值、趋势、告警表；在右侧配置标题、单位、范围、图例、列与显示样式。摆放位置和数量自由选择。
5. **绑定数据**：选泵，在同一工作区右侧“动态”选择运行、故障、模式、频率测点。需要新点时打开点表，选完回到原设备，不丢失位置或选中状态。可先画后接数据，也可先建点表。
6. **设交互、试工况**：选择“点击打开设备面板”“打开趋势”“切换画面”等常用动作；切到预览检查运行、停止、故障、数据失效。模拟数据和现场数据有明确标识。
7. **保存、发布**：保存草稿，检查引用、必需绑定和资源，发布指定版本。独立展示端验证画面与绑定；继续编辑不会改变当前发布版本。

不再要求用户在“选场景、编辑、绑定、发布”四个互相隔开的页面反复切换。发布前检查直接定位到问题对象。

编辑器外壳用中性的浅灰、清晰边界和稳定工具位置，深色驾驶舱只是画布主题。主操作针对工程人员的大屏电脑；1366×768 时面板可折叠，不为手机制作模式缩减绘图能力。

## 3. 首个正式版本必须具备的工具

### 3.1 通用绘图和排版

| 能力 | 最低交付要求 |
| --- | --- |
| 基础绘图 | 矩形、圆/椭圆、直线、折线/多边形、文字、图片、本地 SVG；文字能编辑字体、字号、颜色、对齐和换行 |
| 选择与变换 | 单选、Shift 多选、框选、8 点缩放、旋转、复制、删除、方向键微移；工具状态与鼠标反馈明确 |
| 布局 | 网格吸附、参考线、六向对齐、等间距分布、前后层级、锁定/隐藏、组合/解组；组合后连接与坐标不丢 |
| 工作区 | 标尺、缩放、平移、适应画面；1920×1080 画面边界明确，世界坐标不随视口改变 |
| 编辑记录 | 一次拖拽算一次撤销；复制/组合/绑定可撤销；输入框快捷键不被画布劫持；实时数据不进入撤销栈 |
| 保存与资产 | 保存再打开保留对象、连接、样式、绑定；本地图片/SVG 随项目交付，不依赖开发机路径 |

基础图形可自由组合成新的设备外形。组合保存为“我的图元”，下次拖入就是独立实例；首版仅支持明确的属性与测点槽位，无须搭建组件市场。

### 3.2 工业图元与连接

首批图元限定为：**离心泵、风机/电机、开关阀/调节阀、矩形池/水箱、仪表、管道与分支**。每项至少有经典平面和精细平面两种外观预设，使用同一类型、端口、参数和动态属性。池体数、泵数和管网布局不写死；组合件只是这些图元的实例集合。

- 每个设备有名称/位号、方向、尺寸、标签位置；池体有液位方向和量程，仪表有单位、精度和上下限。
- 端口有稳定标识和方位；管道保存源/目标的“对象 ID + 端口 ID”和中间转折点。分支使用明确的连接节点，交叉但不相接的线不隐含连通。
- 支持水平/垂直正交管道、手动转折、箭头、介质颜色、线宽、流动效果。管道可连接设备、分支，也可画开放端并保留未连接状态。
- 移动、缩放、旋转、成组和解组设备后，端点仍跟随；自动布线不能擅自移走用户固定的转折点。
- 管道动画来自明确的状态/流向配置。几何相连不推算实际流量、阀门状态或控制许可。

默认状态包含运行、停止、故障、未知；故障优先于正常运行，数据失效覆盖正常着色。颜色之外保留文字或符号，未绑定不显示正常。动画仅在有效状态下启用。

### 3.2.1 元素的连接点和数据定义必须可编辑

内置图元提供初始值，工程人员可在右侧“元素定义”调整，不需要修改代码或写脚本。基础矩形、文字、图片和组合中的子元素同样可以定义连接点与数据槽位。

| 定义 | 用户可配置的内容 | 保存与运行约束 |
| --- | --- | --- |
| 连接点 | 增删、名称、沿边位置或任意 X/Y 百分比、双向/仅流入/仅流出 | 编号稳定，改名、缩放、旋转不改引用；仍被管道使用时先更换端点再删除 |
| 数据槽位 | 增删、名称、类型、运行/故障/开到位/数值/文字/流动/附加用途、是否发布前必需绑定 | 槽位编号与实际点位 ID 分离；选点按类型过滤，复制实例默认清空实际绑定 |
| 显示规则 | 槽位、比较/区间/枚举条件、颜色/文字/可见性/旋转/流动结果、优先级 | 有效数据才执行正常规则，故障与数据失效优先；不执行任意 JavaScript |
| 我的图元 | 将选中元素和内部管道保存成可复用定义，保留接口、槽位、参数与规则 | 新实例独立编号，内部引用重映射；导出、导入、重开、发布与离线保留定义 |

数据槽位用于定义“这个元素需要什么数据”；实际绑定用于选择“站点的哪个测点提供它”。连接点用于定义图形连接位置，不隐含数据采集地址、控制许可或设备输出。

例如一个自画矩形可定义 `flowReading` 数值槽位、任意位置的 `outlet` 连接点，并配置流量大于阈值时改变填充色。将矩形与其他元素组合保存后，下一张空白画面可放入该图元，重新选择测点即可使用。

### 3.3 驾驶舱组件

首批只做高频种类：面板/标题、指标数值、状态灯、棒图/仪表、折线/柱状/饼环图、数据表、告警/事件列表、导航按钮。图表统一用现有 ECharts。

- 指标名称、单位、小数位、图标、阈值和布局可配，不继承原模板的标题或量程。
- 图表能配置多个序列、左右轴、时间字段、图例、阈值、时间窗口；绑定切换后同步名称/单位，保留用户显式设置的轴范围。
- 趋势支持数值点实时采样与上游历史行数据两种来源。实时采样从接入时开始，缺失时间形成断点，不补出接入前历史。
- 列表/表格能选字段、列名、格式、排序和行数。告警组件先展示现有告警/事件数据；不为视觉组件另造完整告警服务。
- 主题提供灰色工艺、浅色监控、深色驾驶舱三种预设；主题控制色板、字体、边框、间距，不固定页面布局。

01 的四池、05 的泵站今后可以由这些能力组装；其原版视觉质量作为细节参考。三维数字孪生、特殊建模与专用动画并不由二维图元自动获得。

## 4. 数据与动作要自然地附着在对象上

### 点表与选点

沿用 KepServer 风格的“连接/设备树 + 测点表 + 当前值/质量”工作方式。业务画面绑定统一的测点 ID，不直接写 OPC UA NodeId 或 Modbus 地址。

选中对象后右侧列出明确的槽位，如泵的运行、故障、模式、频率；点“选择测点”打开带搜索、类型过滤和预览的表格。OPC UA 可浏览节点多选导入；Modbus 支持表格逐行添加、批量地址与点表导入，保留设备单元、功能码、地址、类型、字序和刷新参数。高级参数折叠，缺少必需信息时在该行说明原因。

第一版继续一个项目使用一个共享采集连接；多源由现有上游快照聚合。保留数据边界，避免为新画布同时重写采集系统。新文档只引用现有点表，未来有确切多源需求再扩展。

### 动态与状态规则

面向用户的配置是“对象属性 → 测点 → 规则”：显示值、文字/颜色、可见性、液位填充、旋转/流动等。提供比较、区间、枚举和简单倍率/偏移；明确规则优先级，不要求写 JavaScript。

运行数据不写回画面文档。质量和时间来自现有归一化层：`0`、`false` 有效；缺失、坏质量、过期、离线显示未知和原因；现场连接不回退演示数据。归一化数字量不再次取反。需要模拟量原码换算时固定使用 4000～20000，工程量程属于正常配置参数。

### 事件与设备面板

第一版事件只提供打开设备面板、打开趋势、切换画面和打开链接。设备面板共用泵/风机、阀门、模拟量三个基础类型，展示绑定读数、模式、联锁和质量。

本轮保留真实连接只读；本地演示操作继续使用已有确认和演示审计。未来实际控制属于单独接入阶段，复用现有保护，区分命令已接收与新鲜反馈确认，不能点击图形后直接把显示值改成成功。不因本次重订方案增加认证体系、微服务或权限平台。

## 5. 技术实现：采用成熟画布，自己实现业务模型

### 选型结论与边界

采用 **AntV X6 + 现有 Vue 工作区 + ECharts + 现有数据/发布服务** 作为首轮实现路线。X6 提供 SVG/HTML 节点、连接端口，以及选择、变换、吸附、历史等工具基础；工业图元、状态规则、表单体验和发布兼容仍由本项目实现。它不是现成 SCADA 产品。

本次已用锁定的 X6 `3.1.7` 建立独立技术样机，验证内容与结果单独记录在第 8 节。正式集成再锁定依赖和离线打包，不引入运行时 CDN。

| 路线 | 本项目判断 |
| --- | --- |
| 继续原 DOM/CSS 场景提取 | 适合保留旧场景显示；无法成为新绘图模型，停止作为新画布基础 |
| 手写 SVG 全套编辑器 | 可行，但选择/操控柄/连线/撤销要自行维护，本轮投入不合理 |
| Konva / Fabric | 适合自由绘图；本项目还需承担设备端口图、管网和 ECharts 叠层协调，暂不并用第二套引擎 |
| X6 | 当前主要难点是设备连接、变换及 SVG/HTML 混排，与首版目标匹配；先验证再正式接入 |
| 直接整体引入其他 SCADA 系统 | 可参考成熟编辑交互；整套接管会重复现有应用、数据桥和发布链，本轮不做 |

参考依据为 [X6 官方仓库](https://github.com/antvis/X6)、[变换插件](https://x6.antv.antgroup.com/en/tutorial/plugins/transform/) 和 [历史插件](https://x6.antv.antgroup.com/en/tutorial/plugins/history/)。正式集成必须验证自定义图元缩放、分组、管道操作及图表事件竞争，不能以引擎存在某个 API 代替产品验收。

### 最小结构

```text
Vue 工作区：工具栏 / 图层 / 外观、动态、事件表单 / 现有点表
                            ↓ 编辑指令
画面文档：画布、节点、管道、分组、资源、测点引用、有限规则/事件
          ↓                                 ↓
X6 图元渲染 + ECharts                  现有采集与质量归一化
          ↑                                 ↓
          └──────────── 运行时属性投影 ────────┘
                            ↓
                 现有草稿 / 发布 / 展示 / 离线打包
```

工程实现只分清三件事：可保存的画面定义、可复用的图元定义、随采集变化的运行状态。X6 的具体序列化数据由小型适配层读写，业务绑定和版本不埋在原 HTML 标签或场景 CSS 中。

空白画面必须可独立表示，例如：

```json
{
  "format": "screen-document",
  "version": 1,
  "canvas": {"width": 1920, "height": 1080, "theme": "process-gray"},
  "nodes": [],
  "pipes": [],
  "mappings": [],
  "source": {"kind": "json", "data": "{}", "url": "", "pollMs": 1000, "maxAgeMs": 10000, "demo": true}
}
```

设备实例引用 `symbol: "pump"`、几何、样式与命名槽位绑定；管道端点引用 `{ "nodeId": "pump-1", "portId": "outlet" }`。图元注册表负责默认几何、可配置参数、端口和动态属性，不包含 01/05 场景编号。初期仅冻结本轮实际需要的字段，避免先设计通用脚本语言或复杂组件协议。

预览与发布使用同一文档、图元注册表和显示规则，运行模式关闭编辑手柄。图表随尺寸改变刷新，移除时释放实例/监听器。数据刷新不重新创建画布对象，也不覆盖正在输入的设计属性。

## 6. 新的验收标准

主验收不加载 01/05，不导入原场景子树或整页截图；只允许空白、基础图形、单设备图元和普通图片资产。测试必须通过鼠标、键盘和属性表单创建对象，不以脚本填充成品文档代替用户操作。

| 场景 | 从空白完成的内容 | 必须证明 |
| --- | --- | --- |
| A：新的供水泵组监控 | 一池三泵两阀、分支/干管、液位仪表、数值、趋势、告警条、设备面板；布局有别于原 05 | 逐台放置；连接后移动/旋转/缩放仍跟随；复制后独立换绑；预览到发布完整走通 |
| B：新的运行驾驶舱 | 自定布局的六个指标、双轴趋势、柱图、饼环图、状态列表、事件表及页面导航 | 图表配置和字段可改；同一数值/趋势组件复用 A；无场景 ID 特判 |

两张画面都通过以下检查，才称为可用画面设计器：

- 操作记录能追溯到零对象；保存重开、导入导出、发布端和离线端保持对象与绑定一致。
- 一个设备或图表能独立添加、删除、调整，不要求保留某个完整泵组、四池容器或场景皮肤。
- 成组/解组、批量移动、复制和撤销不损坏管道端口与动作引用；复制出的独立设备默认清空测点，只有明确选择复用绑定时保留。
- 运行、停止、故障、未知及质量恢复正确；真实 `0/false` 不丢失；无数据时不显示演示正常值，缺失历史形成断点。
- 编辑中不执行运行点击动作；运行中不移动对象；切换设计/预览不丢绑定，草稿不修改已发布画面。
- 1920×1080、1366×768、3840×2160 横屏等比展示；编辑工具/面板不遮住选中对象且可收起。
- 工作台连续编辑与预览，图表切换/销毁没有重复实例或控制台错误；正式性能验收先以 300 个可见节点、100 条管道和 6 个图表为目标负载，记录设备与实测结果，不预填帧率成绩。

视觉验收检查对齐、文字层级、设备辨识度、工艺可读性和显示完整性。01/05 可作同工况对照参考，SSIM 不再是核心绘图能力的通过门槛。

## 7. 实施顺序与停止扩张的条件

下表按一名熟悉仓库的开发者估算，共 **22～32 个有效开发日**，不承诺固定日历日期；第一阶段后用实际耗时修订。每阶段有能操作的成果和对应测试，不再先堆模板。

| 阶段 | 估算 | 具体产物 | 出口条件 |
| --- | --- | --- | --- |
| M1 空白画布基础 | 5～7 日 | 正式工作区；基础形状、文字、图片；选择/操控柄/吸附/对齐/分组；新文档保存重开 | 不读原场景，能画分区与标题，创建独立对象，编辑记录正确；旧项目仍能打开 |
| M2 工艺绘图 | 6～8 日 | 独立泵/阀/池/风机/仪表；端口管道、分支、转折编辑；我的图元 | 完成验收 A 的静态画面，移动/变换/分组/复制不断线；图元外观和参数可配 |
| M3 动态、数据与运行 | 5～8 日 | 右侧槽位选点、规则表单、设备面板/有限事件；统一预览、发布/离线支持 | A 在本地模拟和只读测试源下通过设计—绑定—发布；失效/恢复正确，现有质量与只读保护无退化 |
| M4 驾驶舱与交付验收 | 6～9 日 | 可配图表/列表/指标和三种主题；验收 B、复用、性能、操作说明 | 两张新布局由空白完整制作，A/B 和旧格式回归通过；交付可复现证据 |

本轮新增要求贯穿阶段出口：M1 的基础元素能定义连接点和槽位；M2 的工艺与“我的图元”保存这些定义；M3 的槽位按类型绑定点表、规则和设备详情共用定义；M4 的指标、图表、列表及导航通过属性和字段定义完成配置。不能仅给固定设备开放少数预设接口或固定槽位。

M1/M2 没通过前不推进新场景迁移；M3 没通过前不把样机称为可发布产品。完成后才把 A/B 保存为两个示例，供用户参考。是否再增加示例由实际差异决定，不预设必须做满 6 或 12 套。

### 首个实现任务可以直接开工

1. 在现有分支添加独立的新画布入口，新建文档为真正空白；现有现场项目和旧格式不原地转换。
2. 把技术样机的引擎注册、变换、连接抽成小型适配，重写成可维护模块；补足标尺、画面边界、对齐/分组和每手势一次撤销。
3. 完成单个泵、阀、池体的可配置符号；在任意位置摆放、端口连线、移动、旋转、缩放、复制，再保存重开。
4. 将空白作图操作写成正式回归；产出截图与操作记录，再进入数据绑定。旧 V2 片段提取不再作为新图元来源。

每阶段自查后报告可用能力、缺口和验证结果；无须为正常可逆实现逐项申请确认。现场接入继续只读，不操作设备，不推送远端。

## 9. 后续边界

这版交付的是能从空白设计工艺监控和数据驾驶舱的二维组态器。继续迭代应由真实使用中暴露的操作问题驱动，保持同一个画布、数据定义和发布模型，不恢复按模板数量扩张。

项目当前共用一条采集连接；多源由上游聚合。告警列表展示上游已有行数据，不增加告警后端。真实控制写入、完整三维建模、通用脚本、组件市场及生产长期运行验收属于后续独立范围。
